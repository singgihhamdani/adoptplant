💡 Konsep Dasar

Apa itu Analisis Dasimetrik dan bagaimana cara kerjanya?

Analisis Dasimetrik (Dasymetric Mapping) adalah metode yang memindahkan data statistik (populasi) dari unit administratif besar (desa/kelurahan) ke unit yang lebih kecil (piksel raster), menggunakan data pendukung seperti lokasi dan kepadatan bangunan.


Asumsi utama: di mana ada bangunan, di situ ada penduduk. Piksel yang memiliki lebih banyak bangunan mendapat porsi penduduk yang lebih besar.

// Formula Inti Kalkulasi Dasimetrik
Penduduk_Pixel = (A / (B + 0.00001)) x C
  • // A = Bobot Bangunan di Piksel (Luas atau Jumlah)
  • // B = Total Bobot Bangunan di seluruh Desa (SUM)
  • // C = Jumlah Penduduk Desa dari data CSV
  • // + 0.00001 > mencegah pembagian dengan nol

📂 Persiapan Data

Data yang diperlukan sebelum menjalankan plugin.

🗺️ SHP Administrasi Desa

Poligon batas administrasi desa/kelurahan. Harus memiliki field ID unik dan harus dalam Projected CRS (bukan WGS84 geografis). Disarankan UTM.

📊 CSV Jumlah Penduduk

File CSV dengan minimal 2 kolom: ID Zona (harus identik dengan ID di SHP) dan Jumlah Penduduk.

🏠 SHP Open Building

Poligon footprint bangunan. Bisa dari Google Open Buildings (via plugin GEE) atau sumber lain. CRS harus sama dengan SHP Administrasi.

🌎 SHP Area Permukiman

Poligon area permukiman. Untuk mem-filter bangunan agar bangunan industri/pabrik tidak ikut dihitung dalam distribusi.

⚠️
Penting: Sistem Koordinat (CRS)Semua layer input wajib berada dalam CRS yang sama dan harus berupa Projected CRS (mis. UTM WGS 84 Zone 48S / EPSG:32748). Menggunakan CRS geografis (EPSG:4326) akan menyebabkan perhitungan luas yang tidak akurat.

⚖️ Metode Kalkulasi

Dua pilihan pembobotan dan kapan sebaiknya digunakan.

📐 Metode 1: Luas Bangunan (Default)

  • Bobot = akar(min(luas_bangunan, luas_piksel))
  • Bangunan lebih luas = bobot lebih besar
  • Normalisasi Sqrt cegah gedung raksasa dominasi
  • Cocok untuk area campuran hunian dan komersial
  • Lebih sensitif terhadap perbedaan ukuran bangunan

🏠 Metode 2: Jumlah Bangunan

  • Bobot = jumlah centroid bangunan per piksel
  • 1 rumah = 1 suara (tidak peduli ukurannya)
  • 1 piksel 30x30m bisa berisi 0, 1, 2, 3+ bangunan
  • Menggunakan Python/NumPy bincount (akurat)
  • Lebih adil untuk area permukiman padat

📊 Ilustrasi: 1 Piksel Bisa Berisi Lebih dari 1 Bangunan

+------------------------------------------------+ | AREA DESA (Total: 500 jiwa) | | | | +----------+----------+----------+--------+ | | | | HH HH | | HHH HHH | | | | Count=0 | Count=2 | Count=0 | Count=3| | | | 0 jiwa | 100 jiwa | 0 jiwa | 150 j | | | +----------+----------+----------+--------+ | | | H | | HHHH | | | | | Count=1 | Count=0 | Count=4 | Count=0| | | | 50 jiwa | 0 jiwa | 200 jiwa | 0 j | | | +----------+----------+----------+--------+ | | | | Total Rumah = 0+2+0+3+1+0+4+0 = 10 bangunan | | Total Terdistribusi = 500 jiwa (100% akurat) | +------------------------------------------------+
💡
Rekomendasi: Gunakan Metode Luas jika variasi ukuran bangunan signifikan. Gunakan Metode Jumlah jika setiap unit hunian ingin diperlakukan setara (area permukiman padat dan homogen).

🔄 Alur Proses

Langkah-langkah yang dijalankan algoritma secara otomatis.

1

Join CSV ke SHP Administrasi

Data penduduk digabungkan ke atribut tiap poligon desa berdasarkan kecocokan field ID. Desa yang tidak cocok nilainya NULL.

2

Rasterisasi Administrasi Desa

SHP Administrasi diubah menjadi: ID_Zone_Desa.tif (setiap piksel = ID desa) dan Jumlah_Penduduk.tif (setiap piksel = jiwa desa, nilai C).

3

Filter Bangunan berdasarkan Area Permukiman

Hanya bangunan yang berada di dalam area permukiman yang diproses. Bangunan pabrik/gudang di luar permukiman dibuang.

4

Kalkulasi Bobot (A) — sesuai metode pilihan

Metode Luas: Hitung luas tiap bangunan + normalisasi sqrt.
Metode Jumlah: Konversi ke centroid, hitung jumlah centroid per piksel via NumPy bincount, tulis ke GeoTIFF via GDAL Python.

5

Total Bobot per Desa (B) — Zonal Statistics

Menghitung SUM raster bobot (A) per zona desa. Nilai B dikembalikan ke raster, nilainya konstan per desa.

6

Kalkulasi Dasimetrik — Raster Calculator

Formula: (A / (B + 0.00001)) x C. Piksel dengan bangunan dapat porsi penduduk proporsional. Piksel kosong = 0 jiwa.

7

Redistribusi Opsional — Water-filling Algorithm

Jika batas maks/piksel diaktifkan, kelebihan penduduk di piksel padat dibagi ulang ke piksel lain dalam desa yang sama (Soft/Hard Cap).

8

Validasi dan Pembuatan Laporan

Membandingkan total penduduk piksel vs data CSV asli. Menghasilkan laporan validasi HTML + CSV.

🔒 Metode Batasan (Cap Method)

✓ Soft Cap (Disarankan)

Jika kapasitas bangunan di suatu desa tidak cukup, algoritma otomatis menaikkan batas khusus untuk desa tersebut. Tidak ada penduduk yang hilang. Validasi selalu 100% akurat.

✕ Hard Cap (Berisiko)

Batas dikunci absolut. Sisa penduduk yang tidak muat akan dibuang/hilang. Validasi akan menunjukkan selisih besar. Gunakan hanya untuk eksperimen.

📦 File Output

Semua file yang dihasilkan dan tersimpan di Folder Output yang Anda pilih.

🗺
ID_Zone_Desa.tif

Raster zona administrasi desa. Setiap piksel = nilai ID desa. Referensi zona untuk analisis lanjutan.

👥
Jumlah_Penduduk.tif

Raster nilai penduduk flat per desa (nilai C). Semua piksel dalam 1 desa memiliki nilai yang sama.

🏠
Building_Density_Ras.tif

Raster bobot bangunan per piksel (nilai A). Metode Luas: nilai sqrt-luas. Metode Jumlah: jumlah bangunan. Piksel kosong = 0.

📊
Building_Density_Total_Zone.tif

Raster total bobot bangunan per zona desa (nilai B). Nilainya konstan per desa.

⭐
Distribusi_Penduduk_Grid.shp UTAMA

Shapefile grid vektor distribusi penduduk per piksel. Setiap fitur = 1 piksel. Berguna untuk analisis spasial lanjutan.

⭐
Distribusi_Penduduk.tif UTAMA

Raster hasil akhir distribusi penduduk. Setiap piksel = estimasi jiwa dalam area 30x30m. Ini adalah OUTPUT UTAMA untuk analisis selanjutnya.

📋
Validasi_Penduduk.csv

Tabel validasi per desa: Kecamatan, Desa, Populasi Asli (CSV), Populasi Kalkulasi, Selisih, Kategori Kelayakan.

🌐
Laporan_Validitas.html

Dashboard laporan interaktif. Berisi insight analisis, rata-rata margin error, dan ringkasan kelayakan. Buka di browser.

✓ Membaca Hasil Validasi

Cara menginterpretasikan laporan validasi yang dihasilkan.

✓ Optimal
Selisih ≤ 1% — Distribusi sangat akurat. Kehilangan data akibat efek tepi grid sangat minim. Model sangat valid untuk analisis lanjutan.
⚠ Wajar
Selisih 1% – 5% — Penyimpangan dalam batas toleransi. Umum terjadi karena efek pemotongan poligon desa oleh grid (edge effect). Data masih andal.
✗ Periksa
Selisih > 5% — Penyimpangan melebihi batas wajar. Kemungkinan: (1) Desa tanpa bangunan di area permukiman, (2) CRS tidak selaras, (3) Hard Cap dengan kapasitas kurang, (4) Join CSV gagal.
ℹ️
Tentang Desa Selisih 100%:Artinya desa tersebut memiliki data penduduk di CSV tetapi tidak ada bangunan yang terdeteksi di dalam area permukiman. Periksa apakah SHP Bangunan dan SHP Permukiman mencakup desa tersebut.

❓ Pertanyaan Umum (FAQ)

Jawaban untuk pertanyaan yang sering diajukan.

🔴 Error: NameError 'QgsProcessingParameterEnum' is not defined
Import tidak lengkap. Pastikan QgsProcessingParameterEnum sudah ada di bagian import di baris awal file DASSYMETRIC RASTER.py. File yang sudah diperbaiki seharusnya sudah mengatasi ini.
🔴 Error: module 'ee' has no attribute 'Authenticate'
Ada dua package Python bernama ee. Package yang salah ter-install. Solusi: buka Python Console QGIS dan jalankan:

import subprocess, sys
subprocess.run([sys.executable, "-m", "pip", "uninstall", "ee", "-y"])
subprocess.run([sys.executable, "-m", "pip", "install", "earthengine-api", "--upgrade"])

Kemudian restart QGIS.
⚠️ Hasil Distribusi_Penduduk.tif bernilai 0 semua (High:0, Low:0)
Kemungkinan penyebab:
1. Metode Jumlah Bangunan versi lama — Bug pada grid+rasterize sudah diperbaiki dengan Python/NumPy langsung.
2. CRS tidak sama — Pastikan semua layer dalam CRS yang identik.
3. SHP Bangunan tidak tumpang tindih dengan SHP Permukiman — Setelah filter, tidak ada bangunan yang tersisa.
⚠️ Pesan "No spatial index exists for input layer"
Ini hanya peringatan performa, bukan error. Proses tetap berjalan tetapi lebih lambat. Tidak mempengaruhi keakuratan hasil.
❓ Berapa ukuran piksel yang sebaiknya digunakan?
Default 30m cocok untuk data citra Landsat dan Google Open Buildings. Jika ingin resolusi lebih tinggi (mis. 10m), proses akan lebih lambat dan output lebih besar. Pastikan data bangunan juga cukup detail untuk skala tersebut.
❓ Apa perbedaan Soft Cap dan Hard Cap?
Soft Cap: Jika kapasitas bangunan tidak cukup, algoritma otomatis menaikkan batas untuk desa itu. Tidak ada data yang hilang.

Hard Cap: Batas mutlak tidak bisa dinaikkan. Sisa penduduk yang tidak muat akan dibuang. Gunakan hanya untuk eksperimen.
❓ Plugin GEE tidak muncul setelah error. Bagaimana cara memulihkannya?
1. Perbaiki library ee terlebih dahulu (lihat FAQ di atas).
2. Restart QGIS.
3. Buka Plugins → Manage and Install Plugins → Installed.
4. Cari Google Earth Engine plugin dan centang kembali.
5. Tutup jendela. Plugin akan muncul kembali.
❓ Mengapa 1 piksel bisa berisi lebih dari 1 bangunan?
Piksel 30x30m = 900 m2. Rumah kecil bisa hanya 36 m2 (6x6m). Artinya bisa ada hingga 25 rumah kecil dalam 1 piksel.

Pada Metode Jumlah Bangunan, centroid (titik pusat) setiap bangunan dihitung. Jika 3 centroid jatuh dalam 1 piksel yang sama, nilai bobot piksel = 3. Ini perilaku yang benar dan mencerminkan kepadatan permukiman sebenarnya.
